# 串口调试工作台 P2 实施方案

## Context

《串口通信方案》P1（Console 透传链路）已落地：`serial.rs` 打开端口、`session.rs::open_serial` 读写循环、`SerialConnectModal` 连接弹窗、serial 会话直挂 TerminalPane。但当前只是「能通」，调试体验为零——无 Hex 视图、无时间戳、无快捷发送、无 DTR/RTS/Break、无日志。串口工具的核心价值在**调试**，本方案把界面升级为「双栏串口调试工作台」并一次做完 P2 全部能力（用户已确认：双栏形态 + 完整 P2）。

**界面现状诊断（为什么要改）**：
- 串口数据全糊在 xterm 里，二进制/不可见字符直接乱码，无法观察帧边界与时序 → 调试不友好
- 发送靠手敲 + 自己记指令，无预设、无 Hex 发送、无行尾控制、无定时重发 → 人机交互原始
- 无法控制 DTR/RTS/Break（Arduino 复位、ESP32 进下载模式都要靠插拔）→ 交互缺失
- 无收发统计与日志留存 → 信息可视化不足

## 总体设计：双栏调试工作台

serial 会话不再裸挂 TerminalPane，改挂新组件 **SerialDebugPane**（复用 TerminalPane 的 xterm 部分能力）：

```
┌────────────────────────────────────────────────────────────┐
│ 状态条：● COM3 已连接 · 115200 8N1 · [DTR][RTS] · 1.2KB/s↓ · [暂停][清空][记录] │
├──────────────────────────────┬─────────────────────────────┤
│  控制台（xterm，行式/文本流）  │  调试面板（可折叠，默认开）    │
│                              │  ┌─ Hex 监视（收发时间戳+方向 │
│  设备 echo、日志照常显示      │  │  色块+HEX/ASCII 双列）     │
│                              │  ├─ 快捷发送（预设列表+发送框 │
│                              │  │  Hex/文本+行尾+定时重发）  │
│                              │  ├─ 信号控制（DTR/RTS 开关、  │
│                              │  │  Break 按钮、打开预设）    │
│                              │  └─ 统计（RX/TX 字节/速率）   │
└──────────────────────────────┴─────────────────────────────┘
```

**数据流**：终端输入/快捷发送 → DF_STDIN（后端不变）；设备数据 → DF_STDOUT → 同时喂 xterm（文本）与 Hex 监视条目（原始字节）。Hex 时间戳、方向着色、帧边界全部由前端完成，后端零数据面改动。

**调试便利性设计要点**：
- Hex 监视与控制台同屏对照（同一数据两种形态），固定帧条目 + 时间戳精确到 ms，观察设备上报时序一目了然
- 发送路径统一：控制台键盘、快捷发送按钮、定时重发共用同一条 stdin 通道，Hex 监视统一记录 TX（本地回显解决「打字看不见」）
- 高频调试动作（复位、下载模式、心跳轮询）一键化：DTR/RTS 预设 + Break + 定时重发
- 所有调试开销（Hex 缓冲、记录）有上限/开关，不拖慢控制台

## 协议扩展（packages/protocol/src/index.ts + apps/desktop/src-tauri/src/protocol.rs 双端同步）

- `ClientFrame::SerialCtl { s, m: SerialCtlM }`（`t: 'serial-ctl'`），`SerialCtlM`：
  - `{ op: 'dtr', level: bool }` / `{ op: 'rts', level: bool }` / `{ op: 'break', ms?: u32 }`（缺省 250ms）
  - `{ op: 'set-baud', baudRate: u32 }`（运行时改波特率，方便对未知设备扫波特率）
  - `{ op: 'signals' }` 查询 CD/CTS/DSR/RI
- `ServerFrame::SerialCtlResult { s, m: { ok, op, message?, signals?: {cd,cts,dsr,ri} } }`（`t: 'serial-ctl-result'`）
- `SessionOpenedM`（serial 分支）增 `dtr: bool, rts: bool` 初始状态字段（打开时预设）
- `SerialOptions` 增可选 `dtr?: boolean, rts?: boolean`（打开时 DTR/RTS 预设，缺省 true/true 保持现行为）——连接弹窗加对应开关

## 后端改动

### serial.rs（核心重构）
- `SerialChannel` 不再 `tokio::io::split`（split 后拿不回控制方法）。改为**单 select! 双工任务独占 SerialStream**（tokio-serial 5.5.0 实现 `SerialPort` trait，Windows COM 句柄单开，这是唯一干净解）：
  - `Cmd` 枚举经 `mpsc` 送达：`Data(Vec<u8>)` / `Dtr(bool)` / `Rts(bool)` / `Break(ms)` / `Baud(u32)` / `Signals(oneshot 回执)` / `Shutdown`
  - select! 交错处理 `stream.read()`（→ DF_STDOUT）与 `cmd_rx`（写入/控制）
- 控制 API 签名（serialport 4.10.1 实际名字）：`write_data_terminal_ready(&mut self, bool)` / `write_request_to_send(&mut self, bool)` / `set_break(&self)` + `clear_break(&self)` 配对（无 write_break 时长参数，Break = set_break + spawn sleep(ms) + clear_break）/ `read_carrier_detect/read_clear_to_send/read_data_set_ready/read_ring_indicator` / `set_baud_rate`
- `write_input` 改为投递 `Cmd::Data`（保留 5s 写超时语义：对应回执或超时）

### session.rs
- `open_serial`：读写循环收敛进双工任务（`serial_reader` JoinHandle 语义不变，handle_closed 中 abort 照旧）；应用 `SerialOptions.dtr/rts` 预设；`SessionOpened` 带上 dtr/rts
- 新增 `serial_ctl(session_id, m)`：查 `entry.serial`（kind≠serial 报错），转投 `Cmd`；Break 需要时长控制放 serial.rs 内部

### server.rs
- `dispatch` match 加 `ClientFrame::SerialCtl` 臂（仿 `Metrics` 臂带 `s` 转 manager，L213 附近）

## 前端改动

### SerialDebugPane.tsx（新组件，packages/workbench-ui/src/components/）
- 布局：左侧控制台 + 右侧 `Resizable`/拖拽折叠调试面板（antd Splitter 或 CSS resize，折叠态记忆到 localStorage）
- **控制台**：复用 xterm 初始化/theme/font 惯例（参照 TerminalPane L109-151 的 onData/onData 双向），shell 会话不走此组件，TerminalPane 保持不动
- **Hex 监视**：固定帧条目（时间戳 HH:mm:ss.SSS + RX/TX 方向 Tag + HEX 双列 + ASCII 侧栏），环形缓冲上限 ~2000 帧防内存膨胀；工具行：暂停滚动、清空、RX/TX 过滤、HEX/文本切换、自动滚动；时间戳/方向着色全在前端合成
- **快捷发送**：预设 CRUD（内容/Hex 开关/行尾 无|CR|LF|CRLF/标签），存 localStorage（按端口名分组）；点击或 Enter 发送 → `agentSocket.sendInput`（与键盘同路径，Hex 监视记录 TX）；定时重发（间隔 ms，启停按钮，会话关闭自动停）
- **信号控制**：DTR/RTS `Switch`（serial-ctl）、Break 按钮（默认 250ms，可选 100/250/500ms）、连接预设快捷键（Arduino 复位=打 DTR 脉冲、ESP32 下载=RTS/DTR 组合，做成一键按钮）、CD/CTS/DSR/RI 状态回显（连接后查询一次 + 手动刷新）
- **统计**：RX/TX 累计字节 + 滑动窗口速率（字节/s），从数据帧实时累计
- **本地回显**：开（默认）/关；开启时键盘输入与快捷发送在控制台本地显示（串口设备通常不 echo）
- **记录**：开始/停止记录到文件（txt：时间戳+方向+文本；含 Hex 格式），走 Tauri fs/dialog 或后端落盘（与现有日志习惯一致，实现取后端 `serial-ctl` 之外的轻量方案：前端收集 + Tauri save dialog 写盘，避免后端状态）
- 状态条：连接状态（session-closed/serial-lost 帧 → 红色「已断开：原因」）、参数摘要、实时速率、清空/暂停/记录按钮

### 其他
- App.tsx：`kind === 'serial'` 渲染 `SerialDebugPane`（Shell 路径不变）；`SerialConnectModal` 加 DTR/RTS 打开预设开关
- ws.ts / api 层：`sendControl` 已够用，新增 `serial-ctl` 类型封装即可
- TerminalPane 右键菜单按 kind 裁剪（serial 不出「下载所选/删除所选」等 SFTP 项）——若 SerialDebugPane 内嵌的控制台直接不再用 TerminalPane 的菜单，则本项自然满足，择一执行

## 错误与边界
- serial-ctl 打在非 serial 会话 / 会话不存在 → `serial-ctl-result ok:false`
- 控制调用失败（端口消失）→ ok:false + message，不主动杀会话（读循环的 serial-lost 兜底）
- 定时重发与 Break 在会话关闭/组件卸载时必须清理定时器（防幽灵发送）

## 验证
1. `cargo test`（protocol 帧 serde 往返测试补 serial-ctl）+ `cargo build` 通过
2. `npm run build` / tsc 通过（packages/workbench-ui + protocol）
3. 手测（USB 串口或 com0com 虚拟对）：
   - 连接 COM 口，控制台收发正常；Hex 监视同屏显示 RX/TX、时间戳、方向分色
   - 快捷发送文本/Hex、行尾切换、定时重发生效且 Hex 有记录
   - DTR/RTS 开关与 Break（示波器/另一端观察，或 Arduino 复位现象）；运行时改波特率后数据乱→正确
   - 拔线 → 状态条红色「串口断开」+ 会话关闭提示；重插可新建会话
   - 记录文件落盘内容与屏幕一致；统计速率与实际流量相符
