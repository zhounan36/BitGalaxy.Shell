# 统一上传/下载传输服务（SSH / Pet / AI 同一套）

## Context

当前上传/下载有三套并行实现：SftpPane（文件管理器，自有 rid 管道 + transfers 状态）、DropUploadModal（宠物拖拽，独立 SFTP 会话，无任何预检）、toolcore.rs 的 AI 工具（裸 create/write 自带一套）。异常场景（重名覆盖、无权限、磁盘满、超大文件）三处行为不一致且大多直接失败；特大文件（>4GB）落到 FAT32 目标盘必然中途失败。目标：统一为一套「预检 → 交互确认 → 引擎传输 → 分类错误提示」的服务，三个界面与 AI 共用。

已确认的交互决策：

* 重名 = 弹窗三选：**覆盖 / 重命名（默认推荐）/ 取消**

* **≥1GB** 弹确认（显示总大小、目标剩余空间、文件系统格式）；>4GB 且目标盘 FAT32 = 阻断

* AI 异常**不弹窗**：预检结果结构化返回，AI 在对话中说明并等用户指示（工具加 `overwrite`/`force` 参数）

## 协议扩展（双端同步）

* 新 op：`{ op: 'preflight'; direction: 'upload' | 'download'; path: string; to: string; sizeB?: number }`（path=源、to=目标，与 get-*/put-* 语义一致）

* `SftpOpM` 加 `fresh: Option<bool>`（put-file/get-file 认）：覆盖语义 = 全新目标，下载先删 `.part`，上传跳过 APPEND 直接截断重建

* `SftpResultM` 加（均 skip\_serializing\_if，旧客户端透明）：

  * `error_kind: Option<String>`：`permission_denied / no_space / quota / file_exists / text_file_busy / network / unknown`

  * `preflight: Option<PreflightReport>`：`{ sizeB, fileCount, scanTruncated, remoteExists, remoteSizeB, remoteFreeB?, remoteWritable, localExists, localFreeB?, localFs?, localMaxFileB?, suggestedPath?, warnings: [{code, message}], blockers: [{code, message}] }`

  * code 枚举：`target_exists / no_space / fs_4gb_limit / no_permission / large_file / free_unknown / scan_truncated`

## 后端改动（apps/desktop/src-tauri）

1. **Cargo.toml**：新增 `fs2 = "0.4"`、`windows-sys`（Win32\_Storage\_FileSystem feature）
2. **新 src/disk.rs**：本地剩余空间（fs2::available\_space）；GetVolumeInformationW 取卷格式；单文件上限映射（FAT32 → 4GiB-1，NTFS/exFAT → 无限）；含单元测试
3. **src/protocol.rs**：上述结构体/字段扩展
4. **src/sftp.rs**：

   * `pub(crate) async fn remote_preflight(sftp, ...)`：目标 stat + `fs_info`（可用 = blocks\_avail × fragment\_size）+ 临时探针文件 `.bg_probe_<uuid>` 测写权限（用后必删）+ 生成不冲突建议名 `name(1).ext` 递增

   * fs\_info 与探针结果按 (会话, 目录) 5s TTL 备忘，批量同目录预检去重

   * `classify_sftp_error()`：按子串分类（"Permission denied" / "No space left on device" / "Quota exceeded" / "File exists" / "Text file busy" / 连接类）

   * `xfer_upload_one` / `xfer_download_one` 改 `pub(crate)`；`XferState` 加 noop 构造（AI 路径无 WS 出口）

   * `fresh` 分支：下载前删 `.part`；上传跳过 APPEND 判定直接 `create`

   * `send_transfer_done` 失败时带 error\_kind
5. **src/session.rs**：`"preflight"` 分支（组合 remote\_preflight + disk.rs 本地侧）；put/get 透传 `fresh`；`err_sftp` 统一注入 classify——所有 op 错误一次获得分类
6. **src/toolcore.rs** 重写 `run_sftp_transfer`：

   * 复用 remote\_preflight / disk.rs / xfer\_\* 引擎（AI 下载也获得 .part 续传）

   * blockers（无权限/空间不足/FAT32 超限/超尺寸上限）→ 结构化错误返回；AI 尺寸上限由 256MB 提高到 4GiB（预检+确认流程已兜底），超出报 blocker 提示改用主界面

   * `target_exists && !overwrite` 或 ≥1GB 未 force → 成功返回 `{ needConfirm: true, reasons, existingSizeB, suggestedPath }`，AI 转述给用户

   * 参数加 `overwrite` / `force`（默认 false）；确认后走 guard\_write 审批 → xfer\_\*；ToolSpec 描述同步

## 边界情况

* 覆盖 × 续传：`fresh` 解决；用户取消后 `.part` 保留（下次续传资产），不主动清理

* 目录扫描成本：预算制（约 2 万文件 / 3s），超限置 `scanTruncated` 警告放行，sizeB 为下限

* fs\_info None（服务器无 statvfs 扩展）：`free_unknown` 降级，仅保留存在性 + 探针结论

* 浏览器宿主：无本地盘概念，跳过 localFreeB/localFs，只做远端侧（下载走 Blob 无文件系统限制）

* 远端大小反超本地（本地已变化）：仍全量重传，不误续传

* 下载目标同大小文件跳过：保留现有幂等语义
