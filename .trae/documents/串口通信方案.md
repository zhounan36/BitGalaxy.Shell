# 串口通信功能方案（P1 实施版 + 长远规划）

## Context

Shell 目前的会话全部建立在 SSH 之上（shell/sftp/metrics 三种 kind 经 `ConnRegistry` 共享主机连接）。目标：新增**串口（COM 口）会话**，第一步做「控制台透传」——打开本机串口，字节流双向桥接到 xterm 终端面板，复用现有 WS 帧通道与会话生命周期，为后续协议层（Modbus/AT/文件传输）铺路。

核心判断：终端 UI（TerminalPane）与 WS 二进制帧（`DF_STDOUT/DF_STDIN`，帧内嵌 sessionId）对「会话背后是什么」完全无感。串口只是新增一种 kind 的会话来源，数据面零改动。

## 分层模型（长远架构基础）

```
L5  UI 形态层        kind → Pane 映射（serial → TerminalPane；未来 serial-modbus → 结构化面板）
L4  协议语义层       SerialProtocol：谁发起、怎么分帧、文本/二进制（Console / AT / Modbus / XMODEM）
L3  字节流会话层     SerialChannel：读写循环、行尾/回显/Hex/记录、热插拔重连、端口占用处理
L2  链路参数层       serialport crate：波特率、8N1、流控、DTR/RTS、Break
L1  物理电气层       RS-232 / RS-485 / TTL / USB-CDC（应用基本无感；蓝牙 SPP 呈现为 COM 口天然支持）
```

Shell 接管 L2–L4。L1 中唯一影响上层的是 RS-485 半双工多点总线——决定了 Modbus 只能主从轮询。

## 协议类型全景（按 分帧 × 角色 × 形态 三轴分类）

| 类别 | 分帧方式 | 角色模型 | 数据形态 | UI 映射 | 阶段 |
|---|---|---|---|---|---|
| 控制台透传 Console | 无协议分帧，行约定 CR/LF | 人↔设备，全双工 | 文本 | TerminalPane 直透 | **P1** |
| AT 命令 | 行式 CRLF + OK/ERROR 收尾 | 请求-响应 + URC 上报 | 文本 | 终端 + 命令助手 | P3 |
| Modbus RTU | 3.5 字符静默时隙 + CRC16 | 主从轮询，半双工 | 二进制 | 寄存器表格面板 | P3 |
| Modbus ASCII | `:` 起始 + CRLF + LRC | 主从轮询 | HEX 文本 | 与 RTU 共用 | P3 |
| XMODEM/YMODEM/ZMODEM | 起始字符 + 定长块 + CRC 逐块 ACK | 对等逐块确认 | 二进制块 | 复用统一传输服务 | P4 |
| 厂商烧录（STM32/ESP32 ROM loader） | 专有握手帧 | PC→设备 | 二进制 | 透传即可 | 不做 |
| PPP/SLIP | 转义帧 | 对等网络封装 | 二进制 | 系统网络栈 | 不做 |

关键结论：**协议越「文本+行式」越适合直接透传；越「二进制+时序」越必须由后端状态机接管**。Modbus RTU 的时隙分帧若经 WS 前端往返必坏 → P3 的 SerialProtocol 适配器必须住后端，前端只发语义请求。

边界外（明确不伪装成串口）：CAN/CAN-FD（USB-CAN 适配器独立 API）、SPI/I2C/1-Wire（需专用主控硬件）、JTAG/SWD。它们是未来独立的通道 kind。

## 长远架构决策

* **D1 终端通道统一**：PtyShell 与 SerialChannel 收敛为统一写路径（stdin 队列 → write_input），`SessionEntry` 增加 serial 字段；未来本地 shell 同模式接入
* **D2 协议适配器后置**：P1 Console = 纯透传（零转换开销）；P3 引入后端 `SerialProtocol` 状态机（Modbus/AT），与通道解耦
* **D3 kind 命名空间**：`'serial'`（console）→ 未来 `'serial-modbus'` 等，各自映射 Pane，镜像现有 kind 分流模式
* **D4 设备注册表**（P2）：串口档案（端口+参数+标签+自动重连）持久化，对齐 hosts 注册表与 stores 体系
* **D5 传输整合**（P4）：XMODEM/ZMODEM 作为传输引擎接入统一传输服务（preflight → 引擎 → error_kind 分类）
* **D6 热插拔**：读错误 → `handle_closed("serial-lost")` + session-closed 帧；P2 注册表加自动重连

## P1 范围（本次实施）

1. `serialport = "4"`（端口枚举/参数）+ `tokio-serial = "5"`（异步读写 `SerialStream`，Windows 经命名管道桥接）
2. 新模块 `src/serial.rs`：`list_ports()`、`SerialChannel`（打开/读写循环/写超时）
3. 协议扩展（双端同步）：`OpenOptions.serial: SerialOptions`；新帧 `serial-list` / `serial-ports`
4. `SessionManager::open()` 在查主机档案**之前**按 kind=serial 分流（不走 ConnRegistry）
5. 前端：`SessionKind` 加 `'serial'`；侧栏新增「连接串口」入口（端口下拉 + 波特率 + 高级参数）；串口会话直接挂 TerminalPane

### 协议扩展细节

* `SerialOptions { port, baudRate, dataBits(5-8), parity(none/odd/even), stopBits(1/2), flowControl(none/software/hardware) }`，serde default 全可缺省（port/baudRate 必填；serialport 4.x 不支持 mark/space 校验）
* `OpenOptions.hostId`：serial 会话传固定占位 `'serial'`（host_id 保持必填不破坏旧协议；serial 分支不查主机档案）
* `serial-ports` 结果：`{ ok, ports: [{ name, kind, description?, serialNumber? }], message? }`，kind = usb/bluetooth/pci/unknown
* resize 帧对 serial 会话为 no-op（不缓存 pending_size）

### 行为细节

* 读循环：`SerialStream::split()` 读半部 → `DF_STDOUT` 按 sessionId 推回；读 Err（拔线/端口消失）→ `handle_closed("serial-lost")`
* 写路径：复用 `stdin_tx` unbounded 队列 + 专职写任务（5s 写超时），与 shell 完全同构
* 关闭：`SessionEntry` 持 reader 任务 JoinHandle，`handle_closed` 中 abort（与 metrics_task 同模式）；读写两半 drop → OS 关闭端口句柄
* 打开失败错误分类（P1 做基础映射）：权限拒绝/占用 → 「端口被占用（其他程序正在使用）」；不存在 → 「端口不存在（已拔出？）」
* P1 为纯透传：行尾转换（设备只发 CR → CRLF）、本地回显、Hex 视图、时间戳记录、Break、DTR/RTS 预设（Arduino 复位/ESP32 boot）均为 P2

## 演进路线

* **P1（已完成）**：核心链路——serialport 接入、Console 透传、参数打开、终端复用、热插拔断开
* **P2（已完成，调试工作台）**：串口会话升级为双栏调试工作台 `SerialDebugPane`（控制台 xterm + 可折叠调试面板），详见《串口调试工作台P2实施方案.md》：
  * **Hex 监视**：固定帧条目（ms 级时间戳 + RX/TX 方向分色 + HEX/ASCII 双列），环形缓冲 2000 帧，暂停/清空/RX-TX 过滤/本地回显开关
  * **快捷发送**：预设 CRUD（文本/Hex + 行尾 CR/LF/CRLF，按端口名 localStorage 持久化）+ 定时重发（心跳/轮询）
  * **信号控制**：DTR/RTS 开关、Break（100/250/500ms）、Arduino 复位（DTR 脉冲）、ESP32 下载模式（RTS+DTR 时序）、CD/CTS/DSR/RI 查询回显、运行时改波特率（扫波特率）
  * **统计与记录**：RX/TX 累计字节 + 1s 滑动窗口速率；收发记录落盘（txt 含时间戳/HEX/ASCII，Tauri save 对话框 + `write_text_file` 命令）
  * **协议**：`serial-ctl` 帧（dtr/rts/break/set-baud/signals）+ `serial-ctl-result`；`SerialOptions.dtr/rts` 打开预设；`SessionOpened` 回传初始电平
  * **后端**：`serial.rs` 改「单 select! 双工任务独占 SerialStream」模型（split 拿不回控制方法、Windows COM 句柄单开），Cmd 通道承载写入/控制/信号查询；Break = set_break + 定时 clear_break
  * 连接弹窗新增打开时 DTR/RTS 预设开关（Arduino 连接即复位可关）
  * 遗留至 P2 后续：设备注册表与自动重连、时间戳记录到终端、终端右键菜单按 kind 裁剪（SerialDebugPane 不复用 TerminalPane 菜单，自然满足）
* **P3 协议语义**：后端 `SerialProtocol` 适配器框架 + Modbus RTU/ASCII（寄存器表格面板 + 语义请求帧）+ AT 命令助手
* **P4 生态**：XMODEM/ZMODEM 接统一传输服务

本方案与《统一SSH连接注册表方案》（连接生命周期层）、《统一传输服务实施方案》（传输语义层）正交不冲突；串口属于新的「通道类型层」。
