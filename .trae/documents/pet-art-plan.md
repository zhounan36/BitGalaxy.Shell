## 1. 现状诊断（量化证据）

对 `assets/pet/` 全部帧做透明度包围盒测量（alpha>16），结论如下。

### 1.1 同状态内尺寸漂移（动作"发懵/抽动"的直接原因）

| 状态 | 帧宽范围 | 帧高范围 | 宽度方差 | 后果 |
|---|---|---|---|---|
| idle_breath | 320~450px | 472~478px | **36%** | 呼吸循环变成"忽大忽小"的抽动 |
| drag | 414~478px | 390~478px | 15% | 扑腾时角色整体缩放跳动 |
| sleep | 456~478px | 288~472px | 5% / 高度17% | 翻身帧位置跳跃 |
| wave | 318~436px | 466~478px | 27%（抬臂所致） | 部分合理，但含生成噪声 |
| angry | 412~476px | 468~478px | 13% | 头身比例帧间不一致 |

### 1.2 跨状态尺寸不一致（状态切换时角色"突然变大/变小"）

| 状态 | 帧0 宽×高 | 相对 idle_breath |
|---|---|---|
| idle_breath_00 | 374×474 | 基准 |
| ready_00 | 474×478 | **+27% 宽** |
| angry_00 | 476×478 | **+27% 宽** |
| working_00 | 436×478 | +17% 宽（盘坐坐姿） |
| eating_00 | 454×474 | +21% 宽 |
| sleep_00 | 476×458 | 横躺构图，锚点不同 |

### 1.3 根因

1. **逐帧独立生成**：即梦 i2i 补帧每次都是新采样，角色在画布中的缩放/位置无约束（manifest 声称"联合取景框"只统一了裁剪框，没有统一内容比例）。
2. **无归一化管线**：生成后没有"测量→缩放→锚点对齐"的后处理。
3. **关键帧无设计**：8 帧循环缺少 pose-to-pose 关键帧结构，中间帧是随机插值，动作没有时序逻辑。

## 2. 成熟方案调研与取舍

| 方案 | 核心机制 | 可借鉴 | 不采纳原因 |
|---|---|---|---|
| **Shimeji-ee** | 行为层（Behavior XML）与动画层（Frame 序列+锚点）分离；动作结束后自动回落；拖拽/抛掷为独立行为 | 双层架构、动作时长由行为层决定、每帧显式锚点 | 不做屏幕走动（本宠物固定右下角） |
| **VPet-Simulator** | DisplayType 图谱；触摸/工作/睡觉多级反应；随机空闲变体带权重 | 触摸反应叠加在循环态之上（不破坏工作态）、随机 idle 变体 | 数值养成系统暂不需要 |
| **Unity Animator 2D** | 分层状态机：Base Layer（循环）+ Action Layer（一次性动作，带优先级与混合）；Crossfade 过渡 | 优先级中断矩阵、120~160ms 交叉淡化、单一时钟驱动 | 不引入运行时，理念落地到自研轻量机 |
| **Live2D / Spine** | 参数化骨骼，动画无限平滑 | 微动（呼吸/摆尾）程序化生成的思路 | 全套骨骼成本高，AI 生成管线不兼容 |

**采纳结论**：
1. 双层状态机：逻辑循环层（base）+ 动作叠加层（action），动作到时自动回落（Shimeji 思路改造）。
2. 动作带优先级，可被打断/不可被打断显式声明（Unity Animator）。
3. 触摸反应叠加而非切状态（VPet）。
4. 渲染层 rAF 单时钟 + 状态切换交叉淡化（Unity Crossfade）。
5. 循环微动优先用资产稳定性 + 代码微变换表达，而非逐帧重生成（Shimeji 思路 + Live2D 理念）。

## 3. 美术规范 v4

### 3.1 画布与锚点

- 画布：`512×512`，`@2x = 1024×1024`，透明背景（现有资产为白底抠图；**P1 重生成一律改绿幕生成 + chroma key 抠图**，见 §4.2）。
- **锚点（anchor）**：每状态声明归一化锚点，默认站立态 `bottom-center`（画布坐标 x=256, y=492 地面线）。
- 联合取景框沿用（同状态帧共用），但**内容必须先归一化再入画布**。

### 3.2 尺寸基准（头身比恒定是 Q 版角色大小感知的关键）

基准帧：`idle_breath_00`（站立、双手腹前）。所有**站立系状态**归一化后角色高 **474px**、地面线 y=492、水平居中。坐/躺系按姿态声明目标尺寸（坐姿 ≈ 站姿高的 82%，横躺按宽度归一）。

| 状态 | 构图 | 归一化维度 | 目标值（1x） | 锚点 | 帧数×fps | 循环 |
|---|---|---|---|---|---|---|
| idle_breath | 站立 | 高 | 474px | bottom-center | 8×8 | loop |
| idle_blink | 站立 | 高 | 474px | bottom-center | 3×6 | once |
| wave | 站立 | 高 | 474px | bottom-center | 6×8 | once |
| ready | 站立 | 高 | 474px | bottom-center | 4×8 | once |
| angry | 站立 | 高 | 474px | bottom-center | 6×10 | once |
| need_input | 站立+气泡 | 高（仅对齐不缩放*） | — | bottom-center | 4×6 | loop |
| working | 盘坐打字 | 高 | 400px | bottom-center | 8×8 | loop |
| eating | 坐姿干饭 | 高 | 400px | bottom-center | 8×8 | loop |
| sleep | 横躺 | 宽 | 470px | bottom-center | 8×4 | loop |
| drag | 悬空扑腾 | 高 | 460px | center | 6×10 | loop |

\* need_input 若气泡绘制在帧内且位置漂移，先重生成把气泡移出帧（气泡由 UI 层 Bubble 组件负责），归一化退化为"仅对齐"。

### 3.3 帧表设计原则（动作连贯的结构保障）

- **pose-to-pose 三段式**：每循环 = 起始帧 A → 极端帧 B → 回归帧 A'（A' 与 A 逐像素可互为镜像/复制）。极简保障：`帧0 = 帧末帧`，循环必无缝。
- **非循环动作**必须首帧从"基准站姿"出发、末帧回到"基准站姿"（与 idle_breath 帧0 同 pose），保证动作前后衔接无跳变（Shimeji 的 home-pose 约定）。
- 微动（呼吸 ±1.5% 纵向、悬浮 ±4px、摆尾 ±3°）由渲染层程序化变换实现，**不再用生成帧表达**，从根上消灭呼吸抽动。
- 眨眼等局部表情：优先"基准帧 + 眼部覆盖层"两图叠加，资产量从 3 帧→1+1。

### 3.4 manifest v4 新增字段

```jsonc
{
  "states": {
    "idle_breath": {
      "frames": 8, "fps": 8, "loop": true,
      "anchor": { "x": 0.5, "y": 0.961 },     // 归一化画布坐标
      "norm": { "mode": "height", "target": 474 },  // height|width|align
      "homePose": "idle_breath_00"             // 非循环动作的首末帧基准
    }
  }
}
```

## 4. 即梦生成工作流（重生成时执行）

### 4.1 身份锁定（沿用现有做法）

三图参考：官方 Q 版设定稿 + 该状态帧0 + 上一步输出，画布内固定参考节点（`_jobstate.json refBase` 机制保留）。

### 4.2 动作连贯（核心变更）：首尾帧视频抽帧，替代逐帧 i2i

1. 用即梦「首尾帧」视频功能：起始帧=基准 pose 图，结束帧=设计的极端 pose 图，生成 2~3s 动作视频。**所有生成图/视频一律用纯绿幕背景（#00FF00），不用白底**——即梦输出不含 alpha 通道，无法直接透明；绿幕与角色蓝白色系色距极大，chroma key 抠图对白色围裙/蕾丝零风险。
2. `ffmpeg -i action.mp4 -vf fps=8 frames_%02d.png` 抽帧，按帧表挑 6~8 张。
3. 抠背景（替代白底 flood-fill）：chroma key 逐像素软阈值（与绿幕色距 → alpha，保留半透明边缘）+ despill 去绿溢出（G 压回 min(R,B)）+ 1px 羽化。**禁止 flood-fill 白底法**（历史事故：白色围裙/蕾丝被误伤）。
4. 视频帧天然时序连贯，人物比例由首尾帧锚定，漂移远小于逐帧生成。
5. 回环：用「首尾帧」再生成"极端 pose → 基准 pose"段，或直接 ping-pong 播放（0..N..0）。
6. 兜底：视频抽帧仍超差时，用 i2i 低重绘幅度（≤0.45）单帧修补。

### 4.3 提示词模板（附加约束）

```
同一角色，Q版二头身，全身像，正面，
头顶留白6%，脚底踩在画面底部参考线上，角色占画面高度90%，
纯绿色绿幕背景（#00FF00），均匀无阴影无渐变，其他与参考图严格一致
```

### 4.4 质检流程

1. 每状态出 contact sheet（网格拼图）目检比例。
2. 跑归一化脚本（见 §5）`-ReportOnly`，宽/高方差 >2% 的状态打回。
3. 三帧跳检：0 / 中 / 末 帧快速切换预览。
4. 抠图质检：白色围裙/蕾丝内部无抠洞、半透明边缘保留、无绿色溢出残留（放大目检围裙、发梢、白色发箍）。

## 5. 大小统一管线（已交付）

`scripts/normalize-pet-frames.ps1`（零依赖，System.Drawing）：

1. 测量每帧 alpha 包围盒 → 按 manifest v4 的 `norm` 声明缩放（高质量 bicubic）→ 按锚点对齐贴回 512 画布。
2. 1x 计算出的变换参数按 2 倍映射应用到 `@2x`，保证 retina 版同步且不损失清晰度。
3. 默认 `-ReportOnly`（输出前后对照报告），`-Apply` 才写文件；输出到 `-OutDir`（默认 `assets/pet-normalized/`），确认后整目录替换 `assets/pet/`。
4. **验收标准**：同状态帧间 bbox 宽/高方差 <2%；跨状态地面线偏差 ≤1px；`idle_breath` 循环肉眼无缩放跳动。

> 注意：归一化会"压平"呼吸循环中用缩放表达的呼吸感——这是有意的，呼吸感改由渲染层程序化微动提供（§3.3）。

## 6. 状态机 v2（已交付，`packages/pet-ui/src/pet/machine.ts`）

### 6.1 双层架构

```
┌─ Action 层（一次性叠加，到时自动回落）─────────────┐
│ angry(3) > ready(2) > wave(1) > idle_blink(0)      │
├─ Base 层（逻辑循环态）────────────────────────────┤
│ sleep ← idle_breath ⇄ working ⇄ eating             │
│              ↘ need_input（粘滞，确认后回落）       │
│              ↘ drag（粘滞，drag-end/DK 自愈回落）   │
└────────────────────────────────────────────────────┘
display = action ?? base   // 渲染/台词读 display
```

### 6.2 关键规则

- **优先级中断矩阵**：高优先级动作可打断低优先级；`drag` 期间屏蔽新动作；`angry`（错误）最高。
- **触摸反应叠加**（VPet 式）：`poke` 在任意非 drag 态都响应——sleep 起床（ready），其余播 wave，不破坏 base，到时自动回工作/待机。
- **动作末帧驻留**（已放弃 clip-done 方案）：非循环动作（ready/wave/angry）的精灵剪辑短于动作时长，播完后末帧驻留，总时长统一由状态机 `ACTION_MS` 决定，tick 到期清除回落——不依赖渲染层回调，剪辑帧数/帧率与动作节奏解耦。
- **base 计时不受 action 干扰**：working→eating→sleep 的计时在动作叠加期间照常运行。
- **单一数据源**：帧表/时长以 manifest 为准（代码侧 FRAME_TABLE 与 manifest 同步，v4 起含 anchor/norm）。

### 6.3 渲染配套（`PetSprite.tsx`）

- rAF 单时钟驱动翻帧（替代每状态 setInterval）。
- 状态切换 **140ms 交叉淡化**（旧帧定格在下层淡出），消除硬切闪烁。
- 非循环片段播完后末帧驻留，状态机按 `ACTION_MS` 到期切走（渲染层无回调耦合）。
- 程序化微动钩子：idle 循环加 ±1.5% 纵向呼吸（sin，周期 2.4s），替代资产呼吸缩放。
